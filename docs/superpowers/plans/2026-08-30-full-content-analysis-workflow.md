# Full Content Analysis Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the seven-step `FULL_CONTENT_ANALYSIS` Workflow, persist its validated final result and usage data, expose result retrieval, and display progress/results through the existing SSE page.

**Architecture:** Keep the modular monolith and existing Workflow Engine/Event Bus. Add a focused Full Content definition with typed step DTOs, a Finalization service that owns the post-validation transaction, repositories for result/usage reads and writes, and a thin API/UI layer. Keep existing Demo and Structured Demo definitions unchanged for regression coverage.

**Tech Stack:** Next.js App Router, TypeScript strict, PostgreSQL, Drizzle ORM, Zod, Vitest, Tailwind CSS.

**Spec:** `docs/superpowers/specs/2026-08-30-full-content-analysis-workflow-design.md`

## Global Constraints

- Use PostgreSQL + Drizzle ORM only; do not add Prisma or a second ORM.
- Preserve `DEMO_CONTENT_WORKFLOW`, `STRUCTURED_CONTENT_DEMO`, and all existing Phase 6 SSE behavior.
- Use Zod schemas and `z.infer` as the only Step Output type source; no `any`, string JSON handoff, or downstream ad-hoc JSON parsing.
- Finalization transaction must commit before `workflow.completed` is published.
- A real Provider call with missing usage records nullable/unknown token values, never fabricated zeroes.
- Do not implement Phase 8 UI, RAG, MCP, uploads, auth, or external workflow integrations.
- Every production behavior change starts with a failing test and is verified before refactoring.
